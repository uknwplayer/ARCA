# Verified Private Reasoning Transport Attestation V1

## Objective

This milestone removes the blanket V0 prohibition on private `opaque-relay` reasoning without converting `opaque-relay` into a trust-by-label transport.

A private reasoning request is accepted only when the caller supplies an attestation bound to the exact request, payload and verified transport profile.

## Required runtime properties

The attestation asserts the already-tested Durable Opaque Mesh path:

- Opaque Mesh RPC V1;
- Mesh Encrypted Envelope V1;
- X25519 + HKDF-SHA-256 + AES-256-GCM;
- encrypted request and encrypted response;
- ciphertext-only durable state;
- trusted recipient identity;
- signed receipts required;
- restart-safe store-and-return continuation;
- no relay plaintext access;
- Human Review preserved;
- no Core mutation authorization.

The attestation hash covers all fields.

## Correlation binding

`createOpaqueReasoningTransportAttestation(...)` binds:

- requestId;
- payloadId;
- transportId;
- transport profile hash.

An attestation cannot therefore be copied to a different request, payload or transport profile.

## Gate behavior

For non-public `opaque-relay` material, `evaluateReasoningTransport(...)` now requires:

1. a valid bound attestation;
2. transport profile `encryption=end-to-end`;
3. `relayVisibility=metadata-only`;
4. explicit private-processing authorization;
5. provider verification when the transport is external;
6. the existing purpose/privacy/secret checks.

Without the attestation, private opaque reasoning remains fail-closed.

## Important boundary

This attestation opens **transport privacy policy only**.

The resulting transport decision still says:

- `executionAuthorized=false`;
- `coreMutationAuthorized=false`;
- `humanReviewBypassed=false`;
- `payloadPersisted=false`.

Capability matching and authorization remain separate.

## Current limitation

V1's attestation is a local structured assertion generated by the host after selecting the tested protocol stack. It is hash-bound but is not yet a signed remote attestation from the endpoint or an automatically derived proof from durable execution receipts.

The next integration should derive/finalize this evidence from the actual Durable Opaque RPC execution and wire it into a verified `ReasoningProviderRegistry` runtime, so a provider cannot receive the private request through any transport other than the attested encrypted path.
