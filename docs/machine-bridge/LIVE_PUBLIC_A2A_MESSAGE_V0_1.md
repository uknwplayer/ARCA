# Live Public A2A Message v0.1\n\n## Goal\n\nCross the first execution boundary with a genuinely network-reachable A2A server while preserving the discovery trust boundary.\n\n## Preconditions\n\nThe workflow retrieves the public Agent Card over HTTPS with public-DNS pinning. A message is sent only when the card exposes a versioned JSON-RPC interface and does not declare agent-level or skill-level authentication requirements.\n\nSupported protocol profiles:\n\n- A2A 0.3 JSON-RPC: message/send;\n- A2A 1.x JSON-RPC: SendMessage.\n\nOther protocol versions/bindings are rejected rather than guessed.\n\n## Message\n\nThe live query is fixed in source. It asks only for a short description of publicly advertised capabilities and limitations and explicitly instructs the remote agent not to use external tools, modify data, contact third parties, or perform side effects.\n\n## Network controls\n\n- HTTPS only;\n- no credentials;\n- public DNS addresses only;\n- DNS-selected address pinned into the HTTPS connection;\n- redirects refused;\n- bounded request/response size;\n- timeout;\n- text-only request;\n- no streaming;\n- no push notification;\n- no files;\n- no extended Agent Card;\n- exact JSON-RPC response correlation.\n\n## Trust boundary\n\nA successful response remains untrusted external testimony. The workflow explicitly keeps trust, admission, capability verification, role conformance and runtime binding false.\n\nThis capability does not promote a live remote agent into any federation or trust domain. Admission and verification remain separate gates.\n
